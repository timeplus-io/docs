# Understanding Watermark

In stream processing, a watermark is a mechanism used to track the progress of data processing in one or more streams. It helps determine when all events up to a specific timestamp have likely arrived, enabling the system to process time-based operations like [window aggregations](/streaming-query#window-aggregation).

Since stream processing deals with unbounded, out-of-order data, watermarks are essential for defining bounded windows and for discarding late or outdated data in a consistent way. Watermarks allow the system to advance event-time, trigger computations (e.g., closing a [tumbling window](/functions_for_streaming#tumble) and [emitting results](/streaming-aggregations#emit)), and maintain accuracy even when data arrives with delays.

## Watermarks and emit timing

In [Tumble](/tumble-aggregation) and [Hop](/hop-aggregation) aggregations, Timeplus treats the data before the watermark as complete. When the watermark reaches a window's end time, the window can close. If an event arrives with a timestamp earlier than the current watermark, Timeplus drops it as late.

For example, suppose you count orders in five-second windows and set [`WITH DELAY 2s`](/streaming-aggregations#emit_delay). When Timeplus sees an order timestamped `12:00:07`, it subtracts two seconds and reaches the window boundary at `12:00:05`. The window ending at that time can close. In general, Timeplus subtracts the delay from the largest timestamp it has seen so far and uses the last window end at or before that time.

If the dashboard needs a running count, `EMIT PERIODIC 1s` lets Timeplus check for a new result every second, even while the window is open. Those checks use the server's clock (processing time). The watermark still follows the order timestamps (event time). For a global count of all orders, the interval simply sets how often Timeplus checks for a result.

`EMIT ON UPDATE WITH BATCH` uses the same clock to check for updated groups. `EMIT ON UPDATE` can show updates as data arrives, even when the watermark stays the same. See [EMIT policies](/streaming-aggregations#emit) for syntax and examples.

## Window state cleanup

The watermark determines when Timeplus can clear window state. Once a Tumble window closes, Timeplus can clear the running count it kept for that window. Hop windows overlap. For example, with a five-minute window starting every minute, successive windows share four minutes of data. Timeplus keeps the partial counts for those shared minutes until the last window that needs them closes.

A global order count normally keeps its total between outputs. [Aggregation-key TTL](/global-aggregation#ttl-of-aggregation-keys) applies separately to aggregation state that Timeplus moves from memory to disk. The TTL starts when Timeplus writes that state to disk, and the state can be cleaned up after the TTL expires.
